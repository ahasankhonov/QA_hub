# Bug Report Template (the agency — QA standard)

Every bug filed to a tracker MUST follow this exact structure. Provided by the QA lead 2026-08-25.

## Title
`QT – P{Priority} – {User Type / Module} – {Page / Feature} – {Short Bug Summary}`

## Bug Description
Clear, descriptive explanation of the issue and how it differs from expected behavior.
Include user impact when relevant. Reference when applicable: Requirements · Acceptance
criteria · SOW · Figma/design · UX standards · Platform guidelines.

## Repro Steps
1. Open the web browser / mobile application.
2. Log in as required (role).
3. Navigate to: {URL, screen, tab, or feature}
4. Perform the required action.
5. Observe the issue.

## Expected Results
- How the system should behave, grounded in requirements / AC / design / standard UX.

## Actual Results
- Short, precise description of what actually happens.

---
Priority mapping used when the source is a severity rating (adjust per ask):
High → P1 · Medium → P2 · Low → P3. the QA lead confirms/overrides priorities at the approval gate.
Dev-facing bodies stay self-contained prose (no internal QA filenames/paths); attach real images separately.
